## 逻辑工件缺陷/权限/风险检查总表

### 统计概览

| 级别     | 数量     | 说明                          |
| ------ | ------ | --------------------------- |
| **P0** | 5      | 阻断级：存在直接安全/数据/资金风险，必须在上线前修复 |
| **P1** | 14     | 高危级：影响系统稳定性、合规性或可靠性，应在生产前修复 |
| **P2** | 6      | 中危级：影响健壮性或一致性，可在迭代中修复       |
| **合计** | **25** |                             |

---

### P0 — 阻断级（5项）

| #   | 类别   | 问题概要                                                                                                    | 可能影响                                               |
| --- | ---- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 1   | 显性风险 | **Prompt注入漏洞**：Researcher通过`web_search`抓取的外部网页内容直接进入LLM上下文，无任何内容消毒/隔离机制                                 | 恶意网页可注入指令劫持Agent行为，导致数据泄露、错误报告或执行非授权操作             |
| 2   | 权限   | **`local_document_search`无路径沙箱**：`doc_path`参数接受任意字符串，无白名单/路径校验/目录限制                                     | 任何持有该工具的Agent可读取系统任意文件（如`/etc/passwd`、密钥文件），构成越权读取 |
| 3   | 权限   | **Publisher无文件写入目录限制**：`export_markdown`/`export_pdf`/`export_docx`未指定输出目录约束，`filename`/`template`参数无校验 | Agent可向任意路径写入文件，覆盖关键系统文件或注入恶意内容到可执行路径              |
| 4   | 显性风险 | **无内容安全过滤**：从Researcher采集到Publisher发布的全链路中，无敏感信息检测、有害内容过滤或数据防泄漏（DLP）机制                                  | 敏感/机密数据可能被采集并写入公开发布的报告；有害内容可能流入最终交付物               |
| 5   | 缺陷   | **Human节点24小时超时自动批准**：`include_human_feedback: false`时Human节点被旁路，但即使`true`时，24h超时后也会静默批准                | 关键决策（如敏感主题研究、合规审查）在人工缺席时被自动放行，质量关卡形同虚设             |

### P1 — 高危级（14项）

| #   | 类别   | 问题概要                                                                                                                 | 可能影响                                                          |
| --- | ---- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 6   | 权限   | **共享ResearchState无角色级访问控制（RBAC）**：所有Agent共享同一个TypedDict状态对象，无字段级读写权限隔离                                               | Researcher可篡改`review_scores`，Writer可覆盖`sections`，角色间数据完整性无法保证 |
| 7   | 缺陷   | **Reviewer→Revisor循环无最大迭代次数**：Revisor提示"如有重大修改则重新提交审核"，但未定义最大重试轮次                                                    | 可能进入无限循环，消耗大量Token和API调用，最终无法收敛                               |
| 8   | 缺陷   | **工具失败无错误处理策略**：`web_search`返回0条结果、API超时或格式异常时，Researcher无降级方案或回退逻辑                                                  | 研究流程在工具异常时直接中断或产出空内容章节，无优雅恢复                                  |
| 9   | 缺陷   | **配置矛盾**：`task.json`中`include_human_feedback: false`与Human节点设计（超时批准、异步恢复）自相矛盾                                        | 运行时行为不确定——Human节点是否被激活取决于实现层默认值，配置语义含糊                        |
| 10  | 缺陷   | **Outline与Section映射缺失**：`outline`为`List[Dict]`，`sections`为`Dict[str, str]`，但无显式`section_id`字段连接二者                    | 章节内容可能与大纲错位，尤其在并行研究场景下导致内容错配                                  |
| 11  | 权限   | **搜索API密钥管理未定义**：`web_search`支持`tavily`/`google`/`bing`三种来源，但密钥存储、轮换、权限范围均未说明                                        | 密钥泄露将暴露所有搜索API；无轮换策略则一旦泄露无法快速止损                               |
| 12  | 权限   | **Chief Editor为超级权限角色**：拥有`init_research`/`plan_sections`/`run_research`/`review_draft`/`compile_report`全部工具，无任何制衡机制 | 单一角色被劫持即等于整个系统被劫持，无纵深防御                                       |
| 13  | 权限   | **Human节点guidance注入无校验**：人工可通过"Add guidance"注入任意约束，无白名单/格式校验/安全过滤                                                    | 恶意操作者可注入覆盖安全规则的指令，或注入导致Agent异常行为的约束                           |
| 14  | 显性风险 | **无Web搜索速率限制**：`web_search`未定义QPS/并发上限，并行研究（`max_sections=10`）会同时触发大量请求                                              | 触发API封禁、IP拉黑；或产生不可控的API费用                                     |
| 15  | 显性风险 | **异步恢复的状态持久化无加密**：Human节点提到"Save state for async resumption"，但ResearchState存储位置、加密方式均未定义                             | 持久化的研究内容（可能含敏感数据）以明文存储，存在数据泄露风险                               |
| 16  | 显性风险 | **来源可信度无自动化验证**：Reviewer仅凭LLM判断"source quality"，无域名信誉、SSL有效性、内容真实性校验                                                 | 伪造来源、钓鱼网站内容可被采信并写入最终报告                                        |
| 17  | 显性风险 | **无完整审计日志**：`error_log`仅记录错误信息，无操作审计（who/what/when/which-agent）                                                      | 合规审查无法追溯；故障复盘缺乏依据；安全事件无法溯源                                    |
| 18  | 显性风险 | **并行研究无并发控制**：`run_research`触发并行章节研究，但无信号量/队列/优先级调度                                                                  | 大量并发请求压垮外部API或本地资源，导致雪崩                                       |
| 19  | 显性风险 | **LLM Token消耗无预算上限**：8个Agent + 修订循环 + 重试，无成本预算/Token上限/熔断机制                                                          | 单次研究任务成本无上限，修订循环可能产生极高费用                                      |

### P2 — 中危级（6项）

| #   | 类别   | 问题概要                                                                                                | 可能影响                     |
| --- | ---- | --------------------------------------------------------------------------------------------------- | ------------------------ |
| 20  | 缺陷   | **"最少5个来源"未程序化强制**：仅靠System Prompt文字约束，无运行时校验                                                       | Agent可能在实际执行中低于5个来源而不被拦截 |
| 21  | 缺陷   | **报告字数限制（1500-2500词）未程序化强制**：同为Prompt文字约束，无截断/补充机制                                                  | 最终报告可能严重超长或过短            |
| 22  | 缺陷   | **Reviewer评分边界值未定义**：阈值描述为"score < 7"触发修订，但恰好=7时的行为依赖于LLM对`<`的解释                                    | 边界场景行为不确定，可能导致该修订的未修订    |
| 23  | 缺陷   | **导出工具参数不一致**：`export_markdown`有`filename`参数，`export_pdf`和`export_docx`缺少`filename`/有`template`但不一致 | 输出文件命名不确定，多格式发布时文件名不统一   |
| 24  | 缺陷   | **搜索源故障无降级策略**：`web_search`支持三种引擎但无失败自动切换逻辑                                                         | 单一引擎故障即导致研究中断            |
| 25  | 显性风险 | **Publisher元数据无脱敏选项**：报告元数据包含"Author/Organization"，无脱敏/匿名化开关                                        | 组织信息可能在不适宜的场景中被暴露        |

### 修复优先级建议

| 优先级    | 建议时间线   | 核心策略                             |
| ------ | ------- | -------------------------------- |
| **P0** | 上线前必须完成 | 输入消毒 + 路径沙箱 + 内容过滤 + 超时策略重构      |
| **P1** | 生产前应完成  | RBAC + 循环上限 + 错误处理 + 审计日志 + 成本控制 |
| **P2** | 迭代中逐步完成 | 运行时校验 + 参数一致性 + 降级策略             |
