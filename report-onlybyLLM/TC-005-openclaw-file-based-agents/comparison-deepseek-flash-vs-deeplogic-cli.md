# TC-005：直接模型评测 vs deeplogic-cli 评测对比

- **对比对象 A**：[`DeepSeek-FLASH.md`](./DeepSeek-FLASH.md)（直接由模型完成评测，2026-10-21 更新版）
- **对比对象 B**：[`deeplogic-cli.md`](./deeplogic-cli.md) / [`deeplogic-cli.inspect-raw.md`](./deeplogic-cli.inspect-raw.md)（deeplogic-cli 实测）
- **对比日期**：2026-10-21
- **被测文件**：`test-cases/agent-suite/TC-005-openclaw-file-based-agents.md`

---

## 一、结论摘要

1. **定性结论一致**：两种方式都认为 TC-005 存在严重缺陷，当前不适合直接作为生产级多智能体配置使用。
2. **DeepSeek 更新版显著扩大了审查范围**：从文档语义审查扩展到 OpenClaw 官方架构核验、权限审查、安全与合规风险审查。
3. **发现数量不同**：
   - DeepSeek-FLASH：24 项（P0 4 / P1 10 / P2 9 / P3 1）
   - deeplogic-cli：18 项 LLM 缺陷（P0 10 / P1 7 / P2 1），另有 2 项 QC Lint P1
4. **评分不能直接横向排名**：
   - DeepSeek-FLASH 给出总体风险评分 **1.5 / 5（高风险）**，由模型基于完整套件和官方文档核验判断。
   - deeplogic-cli 给出 QDP 规则得分 **52.63 / 100，等级 C，门禁 FAIL**。
   - 两者评分方法、输入粒度和严重级别定义不同，不能据此得出“CLI 认为质量更高”的结论。
5. **高置信共性问题仍然存在**：两个报告在至少 8 个主题上交叉确认，包括文件类型矛盾、路由不闭合、工具与 Skill 契约不足、外部动作风险、用户/记忆数据风险、输出验收不足、Markdown 结构和运行治理。
6. **DeepSeek 更新版新增高价值独有发现**：官方架构事实错误、HEARTBEAT 退役、访问控制缺失、热重载完整性、共享 Skill 供应链和来源不可追溯。
7. **最适合各自的任务**：
   - 完整 Agent 套件的语义、官方架构与安全审查：DeepSeek-FLASH 更新版明显更强。
   - 固定规则的回归检查、CI 门禁和缺陷定位：deeplogic-cli 更标准化、可重复。
   - 最佳实践是两者组合，而不是用其中一个完全替代另一个。

## 二、评测口径对比

| 对比项 | DeepSeek-FLASH 直接评测 | deeplogic-cli 评测 |
|---|---|---|
| 输入理解 | 将文件理解为完整 Agent 套件，并区分 SOUL、AGENTS、USER、IDENTITY、HEARTBEAT、MEMORY | 本次配置将完整 Markdown 注册为 **1 个 Prompt 工件** |
| 工件粒度 | 六类文件分别分析，同时做跨文件关联 | 0 Tool、0 Skill、1 Prompt |
| 评测方法 | 逐行静态审查 + Markdown 解析 + OpenClaw 官方文档核验 + P0–P3 风险分级 | deeplogic-cli L2 + QDP/QD-PM + QC Lint |
| 规则来源 | 模型判断 + 14 项官方参考入口 | 固定 QD/QDP/QC 规则集 |
| 架构核验 | 强：核对文件职责、HEARTBEAT 生命周期、路由配置位置 | 未做官方架构对照 |
| 跨工件检查 | 强：跨六类示例做语义关联 | 缺少独立的多工件组合，CROSS 结论不可用 |
| 权限检查 | 有：Shell、租户、DM、工具与外发权限 | QD-PM 因 Gate-0 前置条件失败而跳过 |
| 安全审计 | 有模型驱动的静态安全与提示注入审查 | 无独立安全审计阶段 |
| 可重复性 | 中低；受模型判断、提示和证据选择影响 | 高；规则、级别、定位和输出结构固定 |
| 证据形式 | 行号范围 + 官方依据 + 症状/来源/后果/修复 | 规则 ID + 严重级别 + 位置 + 影响 + 修复建议 |
| 评分方式 | 总体风险评分 1.5/5 | QDP 规则得分 52.63/100，等级 C |
| 最终门禁 | 定性结论“不通过”，无自动门禁 | Gate FAIL |
| 执行时间 | 未记录 | 291.62 秒 |

### 口径差异的影响

deeplogic-cli 的 QDP 检查面向单个 Prompt。把整个 TC-005 文档作为一个 Prompt 提交后，CLI 会把“测试文档没有任务说明、输入格式和输出 Schema”当成 Prompt 缺陷；这些结论作为“完整套件规范不足”是成立的，但其中一部分也来自**测试容器与 Prompt 对象之间的表示差异**。

DeepSeek 更新版则能识别文档内部的六个示例文件，并进一步核对 OpenClaw 官方架构。因此它更容易发现：

- AGENTS.md 与 HEARTBEAT.md 的职责或生命周期错误
- YAML 注释键和渠道声明矛盾
- Gateway 认证、DM 配对和 allowlist 缺失
- 配置热重载与共享 Skill 供应链风险
- Agent 命名、文件路径和来源元数据不一致

这也解释了为什么 DeepSeek 更新版在“套件结构、官方架构和安全治理”方面覆盖更广。

### 为什么 CLI 的分数更高、P0 却更多

这并不矛盾：

- CLI 的 52.63 分来自 QDP 规则扣分模型，关注的是已配置 Prompt 的规则命中情况。
- DeepSeek 的 1.5/5 是模型对完整套件给出的总体风险评分，同时纳入了官方架构偏差、访问控制、供应链、隐私和审计。
- CLI 本次没有真正执行完整的 Tool/Skill/CROSS/QD-PM 检查，因此其 52.63 分不能代表整个 OpenClaw 套件的综合质量。
- 因此，两份分数只能分别用于各自体系内判断，**不具备直接可比性**。

## 五、直接模型独有或明显更强的发现

DeepSeek-FLASH 更新版在完整套件语义、官方架构和安全治理方面覆盖更广，以下内容没有被 CLI 报告同等程度地检出或定位：

1. **官方架构事实偏差**：`AGENTS.md` 被误作多 Agent 路由配置，路由应放在 OpenClaw 的 `agents.entries` 与 `bindings` 中；`HEARTBEAT.md` 已退役，新工作区不再创建。
2. **访问控制设计缺失**：未设计 Gateway 认证、DM 配对、allowlist 和群组门控。
3. **配置热重载完整性**：没有签名、审批、原子发布和回滚，热重载成为高权限变更入口。
4. **模型配置位置错误**：模型写在 SOUL frontmatter，未体现官方 Agent 模型配置。
5. **共享 Skill 供应链风险**：共享 `~/.openclaw/skills` 没有来源、签名和 Agent 白名单。
6. **来源不可复核**：GitHub 地址不存在，且缺少提交哈希与文档版本。
7. **失败开放风险**：损坏配置“优雅降级”可能让安全规则静默消失。
8. **数据流表述误导**：“所有数据本地存储”不等于数据不会进入第三方消息平台或模型提供方。
9. **安全导向的评分体系**：现有评分权重没有安全、隐私、权限和审计硬门槛。
10. **配置标识语法问题**：电话标识、Slack 键、Agent 名和头像路径不可直接使用。
11. **权限矩阵与威胁模型建议**：报告补充了最小权限矩阵、数据分类和关键威胁模型。

这些发现说明：对于“文件驱动多智能体套件”，仅检查一个聚合 Prompt 不足以完整识别官方架构偏差、配置关系和权限边界。

## 六、deeplogic-cli 独有或明显更强的发现

deeplogic-cli 的规则化检查在以下方面更明确：

1. **任务边界缺失**：未说明最终应输出评测、评分、测试还是总结，QDP 判为 P0。
2. **输入来源与输入格式缺失**：没有声明渠道事件载荷、字符集和长度限制，分别判为 P0。
3. **输出格式与输出 Schema 不完整**：评分表、最终报告字段和汇总方式未定义，判为 P0。
4. **对话/任务终止条件缺失**：没有明确何时停止处理，P1。
5. **负例覆盖不足**：只有语气负例，缺少路由、安全、工具和输出负例，P1。
6. **边界条件示例不足**：缺少空输入、超长输入、未知意图和缺失配置示例，P1。
7. **评测标准含不可操作措辞**：`clear`、`reasonable`、`appropriate` 没有量化定义，P1。
8. **代码块语言标识缺失的精确位置**：QC 直接给出行号 140 和 258。
9. **统一缺陷结构**：每条缺陷都有规则 ID、位置、影响和修复建议，适合作为工程工单或 CI 输出。

## 七、严重级别冲突与人工裁决建议

| 问题 | DeepSeek-FLASH | deeplogic-cli | 差异原因 | 建议裁决 |
|---|---|---|---|---|
| 官方架构事实偏差 | P0 | 未独立识别 | CLI 未做 OpenClaw 官方架构对照 | **P0**：`AGENTS.md` 职责和 `HEARTBEAT.md` 生命周期错误会直接导致落地失败 |
| 路由目标未注册 | P1 | P2 | DeepSeek 将其合并进路由完整性；CLI 按单 Prompt“不可达条件”判断 | **P0–P1**：完整套件口径下应优先按高严重级别处理 |
| 核心文件类型数量矛盾 | P2 | P0 | DeepSeek 视为文档一致性；CLI 视为核心约束冲突 | 建议 **P1**：会误导模型和加载器，但通常不等于整个系统不可用 |
| HEARTBEAT 依赖与退役机制 | P0/P1 | P0 | DeepSeek 同时识别架构退役和外发风险；CLI 识别未声明资源/工具 | 保留 **P0**：既无法按当前架构运行，又涉及核心外联流程 |
| 输出与验收契约不足 | P2 | P0 | CLI 对 Prompt 输出契约采用更高权重 | 建议 **P1**；若该文件要直接充当系统提示词，则 P0 合理 |
| Shell 与外联安全边界 | P0/P1 | P0 | 两个体系均确认高风险 | 保留 **P0** |
| 访问控制与权限隔离 | P0/P1 | 因上游 P0 跳过 | CLI Gate-0 未执行权限检查 | 不能因 CLI 跳过而降低风险，应保留 DeepSeek 的 P0/P1 发现 |

**严重级别不能直接取平均。** 应先确定评测对象究竟是：

- “完整 Agent 套件的配置文件集合”，还是
- “一份将被直接注入模型的单个 System Prompt”。

TC-005 的真实对象是前者，但它目前被压缩成单文件展示。DeepSeek 更新版按完整套件审查，因此其架构与安全结论更贴近原始对象；CLI 的输入适配仍会影响部分严重级别和覆盖范围。

## 九、哪种评测方式更合适

### 适合 DeepSeek-FLASH 的场景

- 首次审查完整 Agent 套件。
- 需要核对 OpenClaw 官方架构、文件职责和生命周期。
- 需要理解角色边界、路由、记忆、权限和多文件一致性。
- 需要发现“规则未显式写出，但跨文件组合后会出错”的问题。
- 需要给出面向架构、安全和产品风险的综合判断。

### 适合 deeplogic-cli 的场景

- 在 CI 中设置稳定质量门禁。
- 对 Prompt 的输入、输出、安全、终止、示例和格式做固定规则检查。
- 需要统一缺陷 ID、位置、严重级别和修复建议。
- 需要跨版本回归，比较同一工件是否新增或修复了特定规则问题。

### 推荐的组合流程

1. **先用 DeepSeek-FLASH 或同类模型审查完整套件和官方架构**，确认文件职责、生命周期、路由、权限与数据流。
2. **用 deeplogic-cli 做可重复的基线门禁**，捕获明确的 QDP、Tool、Skill 和 QC 问题。
3. **拆分 TC-005 内部的六类工件**，分别注册为 Prompt/Skill/Tool 或适合的工程对象，再重新运行 CLI，以启用真正的跨工件检查。
4. **统一严重级别口径**后做人工裁决，重点复核 P0 冲突项。
5. **合并去重后形成唯一修复清单**，避免按两个报告的原始数量直接累加。

## 十、最终判断

### 一致结论

两种评测方式都支持以下判断：

> TC-005 具有清晰的“文件驱动 Agent”设计方向，但当前配置在架构事实、路由闭环、工具与 Skill 契约、安全边界、用户与记忆隔离、输出与验收标准方面存在重大缺口，不能直接作为可靠的生产级 Agent 套件。

### 主要差异

- **DeepSeek 更新版更全面**：同时覆盖完整套件语义、官方架构、权限、安全和供应链风险。
- **deeplogic-cli 更标准化**：规则明确、定位精确、便于自动化和 CI。
- **CLI 的覆盖并不完整**：本次仅检查 1 个 Prompt，权限检查被阻断，跨工件结论不可用。
- **DeepSeek 的评分和严重级别仍由模型判断**：更适合作为高覆盖风险线索，而不是唯一自动门禁。

### 推荐结论

如果必须在两者中选择：

- **评价完整 TC-005 套件的语义、官方架构和安全风险**：优先采用 DeepSeek-FLASH 更新版。
- **建立工程化质量门禁**：优先采用 deeplogic-cli。
- **正式评测或发布前**：采用“模型完整套件复核 + CLI 基线门禁 + 人工严重级别裁决”的组合方式。
