### 口径差异的影响

1. **DeepSeek-FLASH**：
   - 覆盖范围最广，能同时审查文档结构、配置关系、安全、隐私、审计和供应链风险。
   - 更新版引入了官方文档核验，因此新增了“AGENTS.md 职责写错”“HEARTBEAT.md 已退役”等 CLI 未识别的架构事实问题。
   - 仍以模型判断为主，1.5/5 和 P0–P3 分级没有可复算公式，也没有运行证据。

2. **deeplogic-cli**：
   - 将整个文档作为一个 Prompt 提交，会报告“测试文档缺少任务说明”等问题。
   - 这些结论作为“套件规范不足”成立，但部分来自“测试容器与 Prompt 对象之间的表示差异”。
   - 规则定位稳定，适合回归和 CI，但不能替代完整套件的跨文件安全审查。

3. **sanityops-inspect-lite**：
   - 首先进行 **保真度分类**（`summary`），仅运行矛盾类检查，跳过缺失类检查。
   - 有独立的 **Risk Explicit（EX）风险审计阶段**，发现 9 项风险项。
   - Gate-0 条件包括责任边界可定位性和 Tool Schema 完整性，本次 G0-3/G0-4 未满足。

## 五、各方法独有发现

### 5.1 DeepSeek-FLASH 独有或明显更强

1. **官方架构事实偏差**：`AGENTS.md` 被误作多 Agent 路由配置，路由应放在 OpenClaw 的 `agents.entries` 与 `bindings` 中；`HEARTBEAT.md` 已退役，新工作区不再创建。
2. **访问控制设计缺失**：未设计 Gateway 认证、DM 配对、allowlist 和群组门控。
3. **配置热重载完整性**：没有签名、审批、原子发布和回滚，热重载成为高权限变更入口。
4. **模型配置位置错误**：模型写在 SOUL frontmatter，未体现官方 Agent 模型配置。
5. **共享 Skill 供应链风险**：共享 `~/.openclaw/skills` 没有来源、签名和 Agent 白名单。
6. **来源不可复核**：报告指出 GitHub 地址不存在，且缺少提交哈希与文档版本。
7. **失败开放风险**：损坏配置“优雅降级”可能让安全规则静默消失。
8. **数据流表述误导**：“所有数据本地存储”不等于数据不会进入第三方消息平台或模型提供方。
9. **安全导向的评分体系**：现有评分权重没有安全、隐私、权限和审计硬门槛。
10. **权限矩阵与威胁模型建议**：报告补充了最小权限矩阵、数据分类和关键威胁模型。
11. **配置标识语法问题**：电话标识、Slack 键、Agent 名和头像路径不可直接使用。

### 5.2 deeplogic-cli 独有或明显更强

1. **任务边界缺失**：QDP 判为 P0。
2. **输入来源与输入格式缺失**：分别判为 P0。
3. **输出格式与输出 Schema 不完整**：P0。
4. **对话/任务终止条件缺失**：P1。
5. **负例覆盖不足**：P1。
6. **边界条件示例不足**：P1。
7. **评测标准含不可操作措辞**：`clear`、`reasonable`、`appropriate` 没有量化定义。
8. **代码块语言标识缺失的精确位置**：QC 直接给出行号 140 和 258。
9. **统一缺陷结构**：规则 ID、位置、影响和修复建议适合作为工程工单或 CI 输出。

### 5.3 sanityops-inspect-lite 独有或明显更强

1. **保真度分类前置**：识别 `summary` 保真度，区分矛盾类检查与缺失类检查。
2. **独立 Risk Explicit（EX）风险审计**：
   - NL-B-2：渐进式约束放松组合导致安全边界消除（Explicit·P0）
   - NR-S-6：HEARTBEAT 自动邮件发送循环无同意机制（Explicit·P0）
   - NL-A-7：Shell “只读”约束仅靠注释
   - NL-B-10：跨对象条件-行为链
3. **Gate-0 门禁结构**：明确 G0-3（责任边界可定位性）和 G0-4（Tool Schema 完整性）。
4. **Cross 规则完整性**：29 项跨工件检查。
5. **影响展望（Impact Outlook）**：AS-* 攻击面和 FM-* 失败模式候选关联。
6. **自我验证（Stage G）**：ID 回溯、措辞红线、输出契约验证。

**严重级别不能直接取平均。** 应先确定评测对象究竟是：

- “完整 Agent 套件的配置文件集合”，还是
- “一份将被直接注入模型的单个 System Prompt”。

TC-005 的真实对象是前者，但它目前被压缩成单文件展示。DeepSeek 更新版按完整套件审查，因此其架构和安全结论更贴近原始对象；CLI 和 lite 的输入适配仍会影响部分严重级别和覆盖范围。

## 九、推荐使用场景

### 适合 DeepSeek-FLASH

- 首次审查完整 Agent 套件。
- 需要核对工件与 OpenClaw 官方架构、文件职责和生命周期是否一致。
- 需要理解角色边界、路由、记忆、权限和多文件一致性。
- 需要发现“规则未显式写出，但跨文件组合后会出错”的问题。
- 需要形成面向架构、安全和产品风险的综合判断。

### 适合 deeplogic-cli

- 在 CI 中设置稳定质量门禁。
- 对 Prompt 的输入、输出、安全、终止、示例和格式做固定规则检查。
- 需要统一缺陷 ID、位置、严重级别和修复建议。
- 需要跨版本回归比较。

### 适合 sanityops-inspect-lite

- 需要完整框架覆盖（QD-P/QD-S/QD-T/QD-PS/QD-PT/QD-ST/QD-CYC/QD-SS/QD-TT/QC/EX）。
- 需要独立的风险审计（Risk Explicit EX 分类）。
- 需要 Gate-0 结构门禁（责任边界、Tool Schema 完整性）。
- 需要影响展望（攻击面、失败模式候选关联）。
- 零安装、模型执行的轻量级检查。

## 十、推荐组合流程

1. **先用 DeepSeek-FLASH 或同类模型核对完整套件语义与官方架构**：
   - 确认文件职责、生命周期、路由、权限和数据流是否正确。
   - 把 P0/P1 作为首轮架构和安全修复输入。

2. **用 sanityops-inspect-lite 做规则化基线门禁**：
   - 保真度分类确定检查范围。
   - Gate-0 验证结构前提条件。
   - Risk Explicit 审计发现显式风险。

3. **拆分 TC-005 内部六类工件**，分别注册为 Prompt/Skill/Tool 后：
   - 重新运行 sanityops-inspect-lite 或 deeplogic-cli，以启用完整跨工件检查。

4. **用 deeplogic-cli 做补充门禁**：
   - 重点检查 Prompt 输入、输出、终止条件、示例和格式。
   - 保留固定规则 ID 和可回归结果。

5. **统一严重级别后人工裁决并合并去重**：
   - 不直接累加三组缺陷数。
   - 重点复核 P0 冲突项和 Gate-0 阻断项。

## 十一、最终判断

### 一致结论

三种评测方式都支持以下判断：

> TC-005 具有清晰的“文件驱动 Agent”设计方向，但当前配置在架构事实、路由闭环、工具与 Skill 契约、安全边界、用户与记忆隔离、输出与验收标准方面存在重大缺口，不能直接作为可靠的生产级 Agent 套件。

### 主要差异总结

| 方法 | 优势 | 局限 |
|------|------|------|
| **DeepSeek-FLASH** | 完整套件语义、官方架构核验、安全与权限风险覆盖最广 | 评分和严重级别由模型判断，缺少自动门禁与运行验证 |
| **deeplogic-cli** | 标准化、适合 CI、缺陷定位精确 | 单 Prompt 粒度、权限检查被阻断、缺少独立风险审计 |
| **sanityops-inspect-lite** | 框架完整、有独立风险审计、Gate-0 结构门禁 | 保真度受限时跳过缺失类检查 |

### 推荐结论

如果必须在三者中选择：

- **评价完整 TC-005 套件的语义、官方架构一致性和安全风险**：优先采用 DeepSeek-FLASH 更新版。
- **建立工程化质量门禁**：优先采用 sanityops-inspect-lite 或 deeplogic-cli。
- **正式评测或发布前**：采用“模型完整套件复核 + lite 基线门禁 + CLI 规则检查 + 人工严重级别裁决”的组合方式。
